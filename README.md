# System Architecture for Modern Software Products

A course for going from a client idea to a production system:

**requirements → architecture → database → APIs → infrastructure → scaling → security → observability → production.**

This is not a generic system-design interview course. The goal is to look at almost any software requirement and confidently say how it should be built.

## Goal

Given any client idea, produce:

- Architecture diagram
- Database design
- API specification
- Technology selection
- Infrastructure diagram
- Development phases
- Cost estimate
- Risks
- Scaling strategy

## How this repo is organized

Each numbered folder is a **section**. Each `.md` file is a **topic**. Nested folders are subsections.

Content is a skeleton only for now.

## Learning progression

See [learning-path.md](learning-path.md).

1. **Application Architecture** — APIs, databases, authentication, SaaS
2. **Production Architecture** — caching, queues, workers, observability, cloud, CI/CD
3. **Distributed Systems** — event-driven architecture, consistency, scaling, reliability
4. **AI Architecture** — RAG, agents, MCP, AI infrastructure, evaluation
5. **Architecture Consulting** — requirements, system design, cost, technology selection, reviewing existing systems

Level 5 is the target: turning almost any client requirement into a confident build plan.
